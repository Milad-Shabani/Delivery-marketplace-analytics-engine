# Data Dictionary

All tables are synthetic, generated by `src/data_generation/generate.py` with a
fixed seed (`SEED = 20260916`), and written to `data/raw/` by
`scripts/run_pipeline.py`. Derived/analytical tables are written to
`data/processed/` by `src/data_processing`, `src/finance`, `src/forecasting`,
and `src/optimization`.

## cities.csv
| Field | Description |
|---|---|
| city_id | Primary key |
| city_name | City name |
| city_tier | 1 = largest metro, 3 = smallest |
| demand_weight | Relative demand weight used to allocate customers/orders |
| delivery_cost_per_km | City-level rider cost per km |
| rider_base_pay_per_order | Fixed rider pay component per order |
| avg_commission_rate | Reference commission rate for the city |

## zones.csv
| Field | Description |
|---|---|
| zone_id | Primary key |
| city_id | Foreign key → cities |
| zone_name | Zone label |
| density_weight | Relative order/rider density |
| avg_delivery_distance_km | Baseline delivery distance for the zone |

## restaurants.csv
| Field | Description |
|---|---|
| restaurant_id | Primary key |
| zone_id, city_id | Location |
| cuisine | One of 15 cuisines |
| restaurant_tier | Budget / Mid / Premium |
| commission_rate | Platform take rate on food_value |
| base_aov | Restaurant's baseline order value |
| avg_food_prep_minutes | Average kitchen prep time |
| average_rating | 1-5 |
| join_date, active_status | Lifecycle fields |

## riders.csv
| Field | Description |
|---|---|
| rider_id | Primary key |
| zone_id, city_id | Home zone |
| vehicle_type | Bike / Scooter / Car |
| join_date, active_status | Lifecycle fields |
| speed_factor | Latent delivery-speed multiplier (<1 = faster) |
| reliability | Latent on-time propensity, used to simulate delay |

## customers.csv
| Field | Description |
|---|---|
| customer_id | Primary key |
| city_id | Home city |
| signup_date | ~45% pre-date the reporting window (existing base); the rest sign up progressively during it |
| acquisition_channel | Organic/Referral, Paid Social, Paid Search, Push/CRM, Partnership |
| age_band | Age bracket |
| order_propensity | Latent order-frequency multiplier |
| price_sensitivity | Latent discount sensitivity (0-1) |
| subscription_status | Subscribed / Not Subscribed |

`customers_enriched.csv` (derived) adds `total_orders`, `lifetime_gmv`,
`lifetime_revenue`, `lifetime_profit`, `average_order_frequency`,
`discount_dependency`, `recency_days`, `churn_flag`, and the rule-based
`customer_segment` (see below).

## orders.csv
| Field | Description |
|---|---|
| order_id | Primary key |
| customer_id, restaurant_id, rider_id, city_id, zone_id | Foreign keys |
| order_datetime / order_date / order_hour / day_of_week / is_weekend / is_holiday | Time fields |
| order_status | Delivered / Cancelled / Refunded |
| cancellation_reason | Populated only when Cancelled |
| gross_order_value | food_value + delivery_fee + service_fee (0 if cancelled) |
| food_value, delivery_fee, service_fee, discount_amount | Line-level economics |
| restaurant_commission | food_value × restaurant's commission_rate |
| customer_total_paid | food_value + delivery_fee + service_fee − discount_amount |
| platform_revenue | restaurant_commission + service_fee + 35% of delivery_fee, less a refund offset |
| rider_cost | rider_base_pay + delivery_distance_km × city delivery_cost_per_km |
| payment_processing_cost | 1.9% of customer_total_paid + $0.10 |
| promotion_cost | Equal to discount_amount (marketing-spend view) |
| refund_amount | Populated only when Refunded |
| contribution_profit | platform_revenue − rider_cost − payment_processing_cost − 50% of refund_amount |
| delivery_distance_km, estimated/actual_delivery_minutes, delivery_delay_minutes | Operational fields |
| rating | 1-5, delivered orders only |
| new_customer_flag, subscription_customer_flag | Behavioral flags |
| promotion_id, payment_method | Additional context |

## Derived tables (data/processed/)
- `restaurant_daily_metrics.csv`, `restaurant_summary.csv`, `rider_summary.csv`
- `monthly_financials.csv` — the core monthly P&L + KPI time series
- `cohorts.csv` — signup-month cohorts × months-since-signup retention
- `rfm.csv` — recency/frequency/monetary scores
- `pnl_monthly.csv`, `unit_economics_by_{city,segment,channel}.csv`,
  `cac_ltv_by_channel.csv`, `margin_driver_decomposition.csv`,
  `restaurant_quadrants.csv`
- `forecast.csv`, `forecast_model_selection.json`
- `strategic_plan.json`, `optimization_allocation.csv`, `optimization_summary.json`

## Customer segments (rule-based, see `enrich_customers()`)
`Never Ordered → New → Subscription → At Risk → Churned → Price Sensitive →
High Value → Loyal → Occasional`, evaluated in that priority order against
recency, order frequency, discount dependency, and lifetime contribution profit.
